Mai - Privacy Policy

Last updated: 2 August 2026

Mai is an open-source, self-hosted Discord bot with a cat persona: she chats when spoken to, reacts to keywords, can welcome new members, and quietly moderates servers with AI-assisted content classification. This policy explains what data Mai processes and why. It covers the instance operated by the project maintainer; anyone self-hosting Mai from the source code is a separate, independent operator of their own instance.

In short:
  • Ordinary messages are checked and forgotten: nothing of their content is stored, only IDs, timestamps, and flagged category labels.
  • Message content is written to Mai's database in exactly two cases, both encrypted at rest and both short-lived: her chat memory of messages you deliberately addressed to her (mention, reply, or DM), and, only where a server switched it on, the text of a message she actually deleted, kept for a few hours so staff can review an appeal about it.
  • A record of enforcement actions against you in a server (IDs, category labels, outcome, timestamp: no content) is kept so the escalation ladder and /mod history work.
  • Mai does not sell your data, show ads, build advertising profiles, or track you across servers.

1. Who processes your data

The Mai bot instance you interact with is operated by the maintainer of this project ("the operator", "we"). For privacy questions, see Contact below. Your use of Discord itself is governed by Discord's Privacy Policy, which is separate from this one.

2. What data Mai processes

Moderation (every message in an enabled server)

When moderation is enabled for a server, Mai sends each new message, and each message that is edited, to OpenAI's moderation classifier to check it for policy violations. Where the server has enabled image classification, the links to any image attachments are sent along with it (OpenAI fetches them; Mai does not download or store them). During this check the message text is processed transiently - it is sent to the classifier and used to produce a verdict, but it is not written to any Mai database. Some rules a server can switch on (invite links, a link allowlist, a mention cap, a message-flood rule) are applied inside the bot and send nothing anywhere at all.

If a message is flagged, Mai stores only metadata in a short-lived queue so a scheduled task can enforce a grace period:

  • Discord message, server, channel, and user IDs
  • The flagged category labels (e.g. "harassment")
  • Timestamps (when it was warned, when the grace period ends)
  • The ID of Mai's warning reply

No message content and no usernames are stored in this queue. Rows are removed once the message is deleted or the author removes it themselves.

The enforcement record

When a message is actually removed (or the author removes it during the grace period, or edits the violation out, or staff act through Mai), that outcome is recorded so the escalation ladder can count it and so a server's staff can look up what happened. This record is metadata only: server, user and message IDs, the category labels, what happened, and when. It holds no message text and no usernames, it is per server, and rows are deleted automatically after the operator's retention window (default: 90 days). If an appeal is granted, the strikes it was about are marked as overturned rather than silently dropped, so the correction stays visible to staff.

Staff can also write short notes about a member (/mod note), visible only to staff of that server through /mod history. Those are the team's own words rather than yours, are stored in plaintext, and are pruned on the same window as the record above.

Evidence for appeals (off unless a server enables it)

Deciding an appeal is hard when the message in question is gone. A server can therefore ask Mai to keep the text of the messages she deleted, so a moderator reviewing an appeal can read what it is about. This is the second and narrowest exception to the no-content rule, and it needs two switches: the operator has to configure a retention window at all, and the server has to opt in.

  • Only messages Mai enforced, captured at the moment she deletes them. Attachments are counted, never fetched or stored.
  • Encrypted at rest (AES-256-GCM, the same key as the chat memory).
  • Kept for hours, not days, and then deleted automatically. Setting the window back to zero clears what is left.
  • Read back only through a staff-only button on the appeal entry, shown privately to the one moderator who clicks it, never posted into a channel.
  • A staff pardon that wipes the record (/mod forgive … strikes:true) deletes it too.

Display names

Where a server switches this on, Mai checks a member's display name against the same classifier when they join and when they rename. The name is processed transiently and no copy of it is stored or written into the log. The strongest action she takes is removing the server nickname; a global Discord username is never changed, and she never kicks or bans over a name.

Chat with Mai (mention, reply, or direct message)

When you deliberately address Mai - by @-mentioning her, replying to one of her messages, or sending her a direct message - your message is sent to OpenAI's text generation model, which produces her in-character reply. To give Mai short-term memory so she can follow a conversation, these chat turns are stored in a history table in the bot's own local database. This is the one deliberate exception to the no-content rule.

  • Only messages addressed to Mai are stored here - ordinary server chatter is not.
  • If your message replies to another message, or carries an image, that context is sent to OpenAI along with it so Mai can follow the conversation - but it is not stored: her memory keeps only what you wrote yourself.
  • The message content and username are encrypted at rest (AES-256-GCM, with a key held only by the operator).
  • Rows are automatically pruned after a few hours (default: 48 hours), so nothing lingers long-term.
  • Direct messages to Mai are treated the same way and are subject to the same encryption and auto-deletion.

Reports and appeals

If a server has set up a moderation log channel, two features let you send something to that server's staff by your own deliberate action: reporting a message (right-click → Apps → "Nachricht melden") and appealing a warning (the button under Mai's warning DM, or /mai appeal if your DMs are closed and the warning never arrived). In both cases the text you type in the form is posted into the staff channel of that server, together with the relevant IDs. Nothing is sent unless you press submit, and the reported message itself is only linked, never copied. The decision staff take is written back into that entry, and an appeal decision is also sent to you by DM.

Reactions, welcome messages and GIFs

Keyword emoji reactions and optional welcome messages are generated in real time and store no data about you.

Where the operator has configured a GIPHY key and a server has switched GIFs on, Mai can attach a GIF to a reply. What leaves the bot is a short search term derived from the conversation, sent to GIPHY: no user, server or message identifier goes with it. Search results are cached briefly by search term only, and the GIF's address is not written into her memory.

3. What Mai does not do

  • No selling or renting of personal data.
  • No advertising, ad profiles, or cross-server tracking.
  • Message content is never written to operational logs - only metadata is. (Content may appear transiently in debug-level logs when debugging is explicitly enabled by the operator.)
  • No message content in the staff log channel: entries carry IDs, category labels, timestamps and a link, never a copy of what was written. The only exceptions are the text you typed yourself into a report or an appeal form.
  • No storage of the content of messages that were merely checked. Only the two cases named above are stored at all.

4. Third-party services

To function, Mai relies on the following processors:

  • Discord - the platform Mai runs on; messages and IDs originate there (privacy policy).
  • OpenAI - classifies messages for moderation and generates Mai's chat replies (privacy policy). Message text is sent to OpenAI to produce a result.
  • Cloudflare - provides the secure tunnel that connects Discord to the bot (privacy policy).
  • GIPHY - only where GIFs are enabled, and only a search term, with nothing that identifies you or your server (privacy policy).

All other processing - the moderation queue, the grace period, chat memory - happens inside the bot itself, on infrastructure controlled by the operator. No further third party receives your messages.

5. Data retention

  • Moderation queue metadata: deleted as soon as the flagged message is removed or the grace period is enforced (typically minutes).
  • Chat history: automatically deleted after the configured window (default 48 hours).
  • Enforcement record and staff notes: metadata only, deleted after the operator's retention window (default 90 days).
  • Appeal evidence: off by default; where a server enables it, hours rather than days, then deleted automatically.
  • Content of messages that were only checked: not retained at all.
  • Operational counters: per-day totals of API calls and tokens per server and model, with nothing identifying a member.

6. Your rights

Depending on where you live (e.g. under the EU/UK GDPR), you may have the right to access, correct, or delete personal data, and to object to processing. Because Mai stores almost nothing and auto-deletes chat memory within a couple of days, most data is short-lived by design. You can clear Mai's chat memory of yourself at any time and without asking anyone, with /mai forget; that deliberately does not touch the enforcement record, which is a server's moderation history rather than chat memory, and which the appeals process depends on. For anything else - for example having that record removed - contact the operator (below), bearing in mind that a server's own staff can already do it with /mod forgive. Requests about data held by Discord, OpenAI, or Cloudflare should be directed to those providers.

7. Children

Mai is used through Discord, which requires users to be at least 13 years old (or older where local law requires). Mai is not directed at children under 13.

8. Security

Mai runs in a hardened container (read-only filesystem, dropped privileges, non-root user, secrets kept out of source control). Chat memory is encrypted at rest with AES-256-GCM. No method of transmission or storage is completely secure, but data is minimized and short-lived by design.
